# Генерування сайту

Сайт поєднує `README.md`, посібник, журнал і сторонні повідомлення. Конфіденційність і локальні дані мають окремі розділи. Коротка політика лишається на GitHub; старі якорі ведуть до посібника. Англійські оригінали — джерело сайту й репозиторію. Повні переклади — у `website/translations/<language-region>/`. Збирання, тести й технічні нотатки залишаються на GitHub із посиланнями до `main`. Nilesoft має довідник кожною мовою; технічні документи також доступні польською, нідерландською й українською.

Генератор виявляє мовні каталоги з `locale.json`, чотирма джерелами, політикою й довідником Nilesoft. Формує перемикач над навігацією з власними назвами мов і прапорами Unicode. Включений шрифт прапорів Noto Color Emoji за OFL працює й у Windows без зовнішньої служби.

`assets/favicon.ico` містить оригінальний кадр 16 × 16 із `src/res/FileSpacer.ico` без передискретизації. Синхронізуйте після генерації піктограми. `favicon_ico` використовує його кожною мовою.

Порядок та ієрархія заголовків відповідають англійським. Генератор нормалізує рівні, зберігає англійські ID й переписує посилання. Зміна мови зберігає розділ. Відсутні документи, заголовки чи локальні PNG/GIF переривають збирання. Нейтральний логотип спільний. Див. [підтримку перекладів](translations/README.md).

Кожна мова має окремі збирання Just the Docs, навігацію, пошуковий індекс, написи й медіа з тією самою закріпленою темою. Невелике перевизначення макета перекладає пропуск до вмісту й версіонує скрипт для оновлення пошуку. Зберігайте MIT-повідомлення й перевіряйте при зміні теми. README репозиторію не має перемикача чи мовних посилань.

Верхня панель посилається лише на репозиторій. Завантаження й позначки походять із Markdown; генератор не додає другої кнопки й не виводить її з журналу.

PNG/GIF — малі пов’язані мініатюри. Локальний скрипт відкриває нативний HTML-діалог із перекладеним закриттям, Escape, клацанням тла й відновленням фокуса. Без JavaScript/діалогу посилання відкриває зображення. Тема не має вбудованого переглядача; додаткових бібліотек/CDN немає. SVG-логотипи не є знімками. Хеш вмісту в URL оновлює мініатюри й перегляд після заміни.

`lunr/custom-index.js` використовує Unicode-обрізання слів для перекладів без англійських основ/стоп-слів. Типове ASCII втрачало б грецькі слова. Англійська зберігає початковий конвеєр. Тестова залежність відповідає Lunr 2.3.9 теми.

<a id="local-checks"></a>

## Локальні перевірки

Із Node.js 22 або новішим у корені:

```cmd
npm ci --prefix website --ignore-scripts
npm test --prefix website
npm run generate --prefix website
```

`build/site-source` — вхід Jekyll, не готовий сайт. Англійська в корені, інші під `_locales/<language-region>`. `locales.json` описує збирання/шляхи. Зберіть кожне через Jekyll і об’єднайте за `path`: англійська в корені, інші в `/de/`, `/el/`, `/es/`, `/fr/`, `/it/`, `/nl/`, `/pl/`, `/pt/`, `/uk/`. Результати генеруються й ігноруються Git. Збирання програми окреме.

<a id="shared-website-and-offline-builds"></a>

## Спільне збирання сайту й офлайнової довідки

`.github/scripts/build-docs.mjs` керує всім конвеєром: генератор, Jekyll усіх мов і збереження закріпленої теми, навігації, пошуку й медіа. Ruby-залежності лише для збирання зафіксовані в `.github/scripts/Gemfile.lock`. Генерація потребує Node.js 22+, Ruby 3.3 і Bundler; читання — ні.

У CMD в корені одноразово інсталюйте залежності:

```cmd
npm ci --prefix website --ignore-scripts
cd .github\scripts
bundle install
cd ..\..
node .github\scripts\build-docs.mjs --target web
node .github\scripts\build-docs.mjs --target offline
```

Результати — `build/site` і `build/offline-docs`. Офлайновий варіант робить посилання/ресурси відносними до HTML і вбудовує пошукові дані в скрипт, тому `file://` працює без сервера. Індексація/токенізація незмінні. Зміна завантажувача теми зупиняє генерацію до перевірки адаптації.

Обидва процеси використовують `.github/actions/build-docs` для залежностей і цілі. Випуск бере той самий тег для програми й документації; не завантажує опублікований сайт і не чекає Pages.

Офлайновий результат містить відбиток джерел, хеші й мови. Пакування перевіряє їх перед повторним використанням. Текстові хеші нормалізують CRLF/LF для Linux–Windows. Відсутнє, застаріле чи пошкоджене перебудовується. Згенерований include NSIS інсталює документацію й видаляє лише власні файли; стороння довідка лишається.

## GitHub Pages

Pages збирає й перевіряє відповідні PR: одноразово генерує джерела, читає `locales.json`, збирає мови й розгортає. Другої мовної таблиці в CI немає. Push до `main` перебудовує за змін README, `BUILD.md`, `docs/`, перекладів, піктограм, генератора, спільної дії чи Pages. PR мають ті самі фільтри й лише збирають. Можливий ручний запуск.

Pages і випуск не запускають один одного: спільна `build-docs` має цілі `web` і `offline`. Теги запускають лише випуск; довідка чекає тестів і використовує їхній коміт. Push документації не випускає програму; обидві зміни в одному коміті все одно дають один Pages-запуск на push гілки.

Англійські оновлення не чекають перекладів. Генератор зберігає текст та ID й повідомляє застарілість анотаціями й таблицею. Реєстрація джерел: [посібник перекладів](translations/README.md).

Після push процесу виберіть **Settings > Pages > Source > GitHub Actions**. Адреса — `https://lebenco.github.io/FileSpacer/`; `_config.yml` задає шлях проєкту для ресурсів і пошуку.

Поле **About > Website** може показувати адресу. Зміна включених документів потребує оновлення `sources` у `generate.mjs`. Фільтри Pages охоплюють усі `docs/` і README; додайте фільтр для нового входу поза ними.
