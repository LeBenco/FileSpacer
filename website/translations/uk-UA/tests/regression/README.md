# Регресійні тести

Еталонний засіб запуску — `tests.cmd` у CMD в корені. Збирає Debug через MSVC/NMAKE й вибирає незалежні тести цього дерева. Джерела, програми й допоміжні засоби мають походити з однієї ревізії. Залежності: [збирання](../../docs/build.md).

<a id="run-locally"></a>

## Локальний запуск

Закрийте FileSpacer. Тести UI потребують розблокованого інтерактивного робочого стола Windows x64, PowerShell 5.1 і тимчасового каталогу NTFS. Залиште клавіатуру й мишу тесту. Закрийте Панель керування перед її зовнішнім тестом. Internal не потребують фізичного введення, але іноді використовують справжні об’єкти Windows/COM.

```cmd
tests.cmd -Category Internal
tests.cmd -Pattern "12-navigation-spatiale\*"
tests.cmd -Category UI -Pattern "16-redimensionnement-alt\03-*"
tests.cmd
```

Під час розробки запускайте нові й відповідні тести. `tests.cmd` без фільтрів запускає весь набір програми; GitHub теж підтримує це. Не повторюйте нативний тест, уже включений до вибраного набору.

| Параметр | Значення |
| --- | --- |
| `-Category Internal\|UI\|All` | Фільтр оголошеної категорії; типово `All`. |
| `-Pattern "group\case-pattern"` | Шаблон PowerShell для відносного шляху; типово `*`. Поєднується з `-Category`. |
| `-Scope Application\|All` | Обидва вибирають набір програми; типово `All`. |
| `-TimeoutSeconds N` | Строк тесту 30–3600 с, типово 300. Перевищення — помилка. |
| `-RunDirectory "path"` | Запис/копія звітів у новий каталог без перезапису. |
| `-VM "name"` | Вибрані тести в налаштованому Hyper-V. |

Для перегляду вибору **без збирання й тестів** викличте засіб PowerShell безпосередньо. `tests.cmd` збирає перед передаванням аргументів, зокрема `-ListOnly`.

```cmd
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\regression\Run-Regression.ps1 -Category UI -Pattern "30-tri-melange\*" -ListOnly
```

JSON містить шляхи, категорії й області; використовуйте його замість сталої кількості тестів. Деякі тести сумісності готують дані з Git-тегів; потрібна відповідна історія.

Засіб UI тимчасово підтримує активність системи/дисплея й призупиняє заставку, відновлюючи стан і після помилок. Не змінює план живлення й не розблоковує Windows. Відновлення записує `desktop-activity.json`.

<a id="run-in-hyper-v"></a>

## Запуск у Hyper-V

```cmd
tests.cmd -VM AgentWin10 -Category Internal
tests.cmd -VM AgentWin10 -Category UI -Pattern "16-redimensionnement-alt\03-*"
```

Хост збирає програму й вибрані нативні/C#-засоби перед передаванням. Клієнт перевіряє хеші й виконує ті самі сценарії/твердження без збирання в гості чи переходу на робочий стіл хоста. Вибір передує пакуванню. Підготовка й діагностика: [Hyper-V](../client/README.md).

<a id="run-on-github"></a>

## Запуск у GitHub

GitHub Actions використовує [робочий процес регресії](https://github.com/LeBenco/FileSpacer/blob/main/.github/workflows/regression.yml) для того самого набору тестів програми. Його можна запустити на вимогу; звичайні надсилання гілок і pull request не запускають його.

У **Actions > Test FileSpacer regressions > Run workflow** виберіть `ref` (гілка/тег/коміт), `category`, `pattern`. `All` / `*` запускає все. Для ручного запуску процес має бути в типовій гілці, а вибрана ревізія — містити потрібні процес і засіб; тести не беруться з іншого дерева.

Процес один раз визначає ревізію, збирає Debug на `windows-2022` і запускає підготовлені тести на інтерактивному столі. `-CI` лише для хостованих засобів GitHub, без `-VM`/`-Prepared`. Той самий користувач працює з обмеженим токеном середньої цілісності; підготовка перевіряє `Shell.Windows()` і токен. COM-реєстрація користувацька. Це не замінює Windows 10 чи інші потрібні конфігурації.

Робочий процес не публікує інсталятор чи автономну довідку. [Робочий процес випуску](https://github.com/LeBenco/FileSpacer/blob/main/.github/workflows/release.yml) повторно використовує його як перше завдання в тому самому запуску, а потім збирає документацію й NSIS із перевіреного SHA. Успішне пакування не є справжнім тестом інсталяції чи оновлення.

Actions показує SHA, підсумки категорій, коди виходу й перші помилки. Журнали, JSON, знімки та `regression-summary.md` зберігаються 14 днів у `regression-<run>-<attempt>`, також після помилок. Помилки робочого процесу/очищення скасовують успіх навіть за пройдених тестів.

## Пошук відповідних тестів

Каталоги `cases/` групують поведінку. Імена й шляхи — сталі селектори; їх не потрібно перекладати.

| Ділянка | Групи |
| --- | --- |
| Стенд і підготовлені артефакти | `00-banc` |
| SQLite, зберігання, квота, подання й журнал | `01`–`02`, `06`–`09` |
| Меню, життєвий цикл, STA й розміри | `03`–`05` |
| Маніфести й сеанси оновлення | `10`–`11` |
| Просторова навігація, настройки й розташування | `12`–`14` |
| Жести й закриття під час взаємодії | `15`–`17`, `24-raccourcis` |
| Збереження подання й команди оболонки | `18-vue-shell-native`, `19-commandes-shell` |
| Навантаження, сповіщення й Панель керування | `20-validation-elargie` |
| Активація, блокування й написи | `21`–`23` |
| Пошук, журнал і Everything | `25-recherche-integration` |
| Розміщення й перегляд Подання | `26-placement-fenetres`, `28-apercu-affichage` |
| Зіставлення типового менеджера | `29-menu-gestionnaire` |
| Локальна довідка й мова | `30-documentation`, `31-langues` |
| Змішане сортування й ідентичності | `30-tri-melange` |
| Меню заголовка й Peek | `33-menu-titre`, `35-apercu-peek` |

Це відправні точки покриття, а не звіт виконання. Перевірте підготовку й твердження тесту перед висновком про покриття зміни.

<a id="native-view-persistence"></a>

### Збереження стану нативного подання

`18-vue-shell-native/02-Persistance.ps1` збирає робочі хост, настройки, вибір, піктограми, фільтр і SQLite зі справжнім поданням оболонки. Перевіряє відновлення, оновлення, фільтр, серіалізацію й знищення/відтворення. Готовність визначають публічні сигнали; сторожовий таймер може провалити тест, але не оголосити готовність.

Окрема діагностика цього стенда:

```cmd
test-native-state.cmd --diagnostic
```

Ініціалізує MSVC x64 й використовує `/Z7` без спільного PDB. Це альтернативний виклик того самого тесту, не додаткова повна перевірка.

<a id="external-applications"></a>

### Зовнішні програми

Справжній тест Everything у групі 25 потребує інстальованої виявлюваної копії без відкритого інтерфейсу в сеансі. Служба сеансу 0 може працювати. `FILESPACER_EVERYTHING_EXE` вибирає інсталяцію, але Виявити також має її знаходити. Шлях записується UTF-16 у `everything-detected.txt`.

Тест запускає приватну копію справжньої програми з власними INI, даними й індексом. Everything читає `run_as_admin` біля програми навіть із `-config`; ізолюйте початковий файл. Інстальовані INI/вибір підвищення незмінні. Твердження читають видимі запити й ідентичність результатів обох областей, не лише процес. `FILESPACER_EXPECT_EVERYTHING_ABSENT=1` вмикає перевірку відсутності в тесті 02.

Тести запуску/протоколу Peek і нативного меню не доводять справжнього відображення Peek/Nilesoft. Дослідіть дані й використовуйте справжню програму для візуального приймання. Відсутність передумов не перевіряє інтеграцію.

<a id="mixed-sorting"></a>

### Змішане сортування

Група `30-tri-melange` перевіряє порядок, настройки, сповіщення, збережені ідентичності й контракт постачальника. Повторно використовує спільні сценарії команд/навігації з увімкненим постачальником. Зберігайте одну реалізацію жестів/тверджень. Фільтр, вільні піктограми, перейменування й видалення показаної папки — важливі межі; самого порядку недостатньо.

<a id="add-or-change-a-case"></a>

## Додавання чи зміна тесту

Розміщуйте тести в `cases/NN-topic/NN-Name.ps1` з точним першим рядком `# Test-Category: Internal` або `# Test-Category: UI`. Використовуйте Windows PowerShell 5.1 та C# 5 / .NET Framework 4.8. Перевірте синтаксис і зберіть засоби до UI. Не присвоюйте автоматичні змінні PowerShell.

Використовуйте `common/` для процесів, збирання, фізичного введення й результатів. Залежності явні: підготовка ВМ аналізує сценарії, шляхи засобів і точні аргументи. Новий динамічний шлях або команда збирання можуть потребувати зміни підготовки. Перевіряйте пряме й підготовлене виконання.

Спостерігайте справжній результат: ідентичність, дієву настройку, геометрію, вибір і фокус. Кількості недостатньо. Не повторюйте невдалу дію, не примушуйте фокус після неї й не змінюйте твердження для PASS. Навмисні помилки доповнюють справжню оболонку, не замінюють її.

<a id="reports-isolation-and-diagnosis"></a>

## Звіти, ізоляція й діагностика

Локальні звіти — у `build/regression/<date>-<id>/`. Зберігайте разом `results.json`, `summary.json`, stdout/stderr, виходи програми й докази. ВМ додає докази розгортання/сеансу/відновлення; див. [структуру звітів](../client/README.md#reports-and-diagnosis).

PASS стосується лише завершених тестів. FAIL, BLOCKED, NOT_RUN, відсутній підсумок, тайм-аут, аварія чи помилка очищення виключають повний успіх. Зберігайте першу помилку й помилки очищення окремо. Окремо звітуйте збирання, функціональні тести й статичний аналіз.

Засіб копіює й відновлює реєстр `/test` і тестову SQLite. Ніколи не скидайте робочі дані. Між тестами видаляє лише тестові ID списків у `Software\FileSpacer\Test\JumpLists`; у межах тесту вони живуть до кінця. Інакше `CommitList` / `FlushFileBuffers` накопичують роботу між наборами. `case-fixture.json` записує очищення. Зовнішні вікна визначайте й закривайте окремо; не завершуйте Провідник для очищення Панелі керування.

Особливості діагностики UI:

- UI Automation показує елементи Таблиці як `DataItem` у `DataGrid`.
- Фізично утримуйте Ctrl до спостереження результату перетягування.
- Перевіряйте фактичну ціль і координати; намір клацнути не доводить доставлення. Для від’єднаних консолей ВМ використовуйте спільні засоби.
- Закінчуйте виключений жест розміру в редакторі імені; відпускання правої кнопки зовні може законно відкрити меню.
- Подвійне клацання може закрити джерело; задайте потрібну політику у тестових даних.
- Скорочуйте шляхи за помилки Win32 206. `/Z7` уникає спільного PDB.

`set FS_SEARCH_TIMINGS=1` записує реальний час читання в `search-observations.jsonl`; 20/01 також пише `load-phases.jsonl`. Журнали не змінюють строків/тверджень. Одночасна перевірка доступності може сильно вплинути на час. Порівнюйте з однаковими спостерігачем, даними й середовищем; час не є універсальним порогом. Стенд не зупиняє зовнішніх засобів інспекції.
