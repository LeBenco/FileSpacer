# Пошук, журнал і Everything

Почніть із `SearchBox`, `FolderWindow::applyNameFilter`, `ShellViewFilter` і `Everything`. Взаємодія: [посібник користувача](user-guide.md#search-and-history).

<a id="local-filtering-and-suggestions"></a>

## Локальне фільтрування й пропозиції

SearchBox відокремлює явне підтвердження від затримки введення 150 мс. Локальний фільтр застосовується через оболонку; пропозиції використовують неактивоване спливне вікно Win32 і нативний список із малюванням власником. Поле зберігає фокус. Для Everything і останніх запитів є одне сховище журналу й один засіб формування записів.

Пропозиція вибирається лише навігацією клавіатурою або натисканням миші. Саме наведення не вибирає Everything; редагування скидає попередній вибір. Enter без пропозиції лишається локальним. Escape закриває список, не стираючи тексту. Tab, втрата фокуса, рух/деактивація та знищення власника закривають вікно. Забезпечте доступність рядків і межі в робочій області монітора.

Лише успішне явне локальне підтвердження, вибір останнього запиту або зовнішній запуск записує непорожній запит. Саме введення не має наповнювати журнал.

<a id="launching-everything"></a>

## Запуск Everything

`EverythingEnabled` за замовчуванням false. Порожній `EverythingPath` означає автоматичне виявлення; `EverythingScope` вибирає поточну папку файлової системи та вкладені (0) або всюди (1). Виявлення перевіряє обидва подання реєстру, App Paths, записи інсталяції voidtools і стандартні розташування програм.

Передавайте один аргумент `-search`. Пошук у папці додає шлях у лапках із кінцевим `\` і групує запит через `<…>`, зберігаючи пріоритет OR. Сам запит лишається в синтаксисі Everything. Вкладені лапки використовують потрійні лапки Everything, окремо від екранування імені програми у Windows CRT. `CreateProcessW` отримує окремий абсолютний шлях виконуваного файлу й доступний для запису буфер команди Unicode без інтерпретатора команд.

Створення процесу підтверджує лише запуск, а не індексацію чи придатні результати. Після успіху очистьте локальний фільтр; після помилки збережіть запит/фільтр і повідомте про помилку.

<a id="history-persistence"></a>

## Збереження журналу

`SearchHistoryLimit` за замовчуванням 5, приймає 0–20. Таблиця SQLite `search_history(sequence,key,query)` відокремлена від стану подання й журналу закритих вікон. Порядкові номери впорядковують запити навіть у межах однієї секунди. Об’єднання збережень стану відкладає запис; звичайне закриття завершує його.

Зміна обмеження транзакційно скорочує журнал кожної збереженої папки, зокрема закритої. Сповіщення містять застосоване обмеження й звичайний/тестовий простір імен, тому відкладені повідомлення не відновлять очищений кеш і не змінять робочі дані з тестового вікна.

Журнал слідує за змінами ідентичності шляху. Тригер видалення `folder_state` прибирає його після підтвердженого видалення, обґрунтованого завершення строку, скидання чи витіснення за квотою. Запис потребує наявного стану папки й не має відтворювати прострочену папку. Сама помилка доступу не є видаленням; діє політика зберігання.

<a id="everything-icon-loading"></a>

## Завантаження піктограми Everything

Пропозиція використовує головну піктограму налаштованого виконуваного файлу, а не включений логотип. Завдання пулу потоків Windows визначає шлях, читає метадані й відображає ресурси через прапорці даних/ресурсів зображень `LoadLibraryExW`. Імпорти модуля не виконуються. `LoadIconWithScaleDown` вибирає зображення для DPI; негайно звільніть модуль ресурсів і збережіть лише власний `HICON`.

Кожне наступне відкриття перевіряє у фоні шлях, час створення/зміни й розмір. Зміни настройок/DPI скидають кеш поля. Оновлення зі збереженням усіх цих значень не виявляється. Малювання бере неблокувальне блокування кешу; відсутність піктограми не заважає дії. Закриття поля скасовує публікацію без очікування потоку; спільний стан і дескриптори дійсні до його завершення.
