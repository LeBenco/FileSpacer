# Поширення через WinGet

GitHub Actions подає `LeBenco.FileSpacer` до публічного [`microsoft/winget-pkgs`](https://github.com/microsoft/winget-pkgs) після успішного **Publish FileSpacer** (`workflow_run`). Поширення має окремі запуск і результат; помилка не змінює успіх випуску. Можливий ручний запуск для вже опублікованого стабільного тега.

<a id="one-time-setup"></a>

## Одноразове налаштування

1. Створіть GitHub **personal access token (classic)** з **public_repo** для власника подань і форка `microsoft/winget-pkgs`. WingetCreate не підтримує fine-grained PAT. Див. [інструкції Microsoft](https://github.com/microsoft/winget-create/blob/main/doc/token.md).
2. У FileSpacer відкрийте **Settings > Secrets and variables > Actions** й додайте секрет **WINGET_TOKEN** із токеном. Не записуйте до процесу, коміту чи журналу. Оновіть після завершення строку або відкликання.
3. Закомітьте й надішліть засоби до типової гілки перед наступним тегом. GitHub завантажує `workflow_run` звідти. Це працює після публікації з `GITHUB_TOKEN`, яка сама не спричинила б `release` іншого процесу.

Звичайного `GITHUB_TOKEN` достатньо для публікації FileSpacer. Додатковий PAT потрібен лише WingetCreate для зовнішнього репозиторію. Ручне створення першого пакета не потрібне: маніфести підтримують перше подання й нові версії.

<a id="each-release"></a>

## Кожен випуск

Дотримуйтеся [процедури випуску](build.md#releases). Після успіху WinGet завантажує `release-publication` саме з цього запуску. Артефакт записує тег і для ручних випусків. Далі:

1. Перевіряє стабільний `vX.Y.Z`, пропускає наявні версії або відкриті PR подання.
2. Завантажує версійований публічний інсталятор і `FileSpacer-update.txt`, звіряє розмір/SHA-256 з маніфестом та доступним хешем GitHub. Не збирає другий інсталятор.
3. Генерує й зберігає YAML версії, англійських метаданих та інсталятора. Охоплює Windows x64, `/CurrentUser`, `/AllUsers`, тихий `/S` і кінцевий аргумент NSIS `/D=<INSTALLPATH>`.
4. Інсталює .NET 9, завантажує WingetCreate 1.12.13.0, перевіряє закріплений SHA-256 і підпис Microsoft Authenticode, перевіряє й подає через `wingetcreate submit`. PAT передається документованою змінною `WINGET_CREATE_GITHUB_TOKEN`.

Інсталятор зберігає типові компоненти й вибір оновлення. Маніфест не просить змінювати типовий менеджер. Подання не означає негайної доступності: перевірки й рецензування Microsoft мають прийняти PR. Стежте за посиланням PR у журналі й відповідайте на зауваження.

Помилка подання зберігає GitHub-випуск і його успіх; помиляється лише поширення. Усуньте причину й відкрийте **Actions > Submit FileSpacer to WinGet > Run workflow**, виберіть типову гілку й опублікований тег. Повторюється лише поширення без збирання/публікації. Відсутній секрет явно спричиняє помилку після збереження маніфестів. Ручний режим також підтримує старі й зовнішні випуски. Невдалі/скасовані випуски нічого не подають. Прийняті версії пропускаються, не замінюються; публічні версійовані файли незмінні.

Після прийняття першого PR та оновлення каталогу:

```powershell
winget install --id LeBenco.FileSpacer --exact --scope user
winget install --id LeBenco.FileSpacer --exact --scope machine
winget upgrade --id LeBenco.FileSpacer --exact
winget uninstall --id LeBenco.FileSpacer --exact
```

<a id="validation"></a>

## Перевірка

Тести поширення в CMD:

```cmd
node --test .github/scripts/winget.test.mjs
```

Охоплюють генерацію маніфестів, придатність випуску, цілісність, обидві області інсталяції й повтори із симульованим HTTP. Не перевіряють NSIS чи справжню оболонку. Команда подання перевіряє схему на Windows GitHub; справжні інсталяція, оновлення, видалення й приймання також перевіряються upstream. Перед першим поданням перевірте обидві області в ізольованій ВМ зі справжнім випущеним інсталятором. Маніфести доступні як артефакт і після помилки.
