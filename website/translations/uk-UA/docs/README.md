# Робота над FileSpacer

FileSpacer — нативний просторовий файловий менеджер C++/Win32. Windows надає подання й файлові операції; FileSpacer — політику вікон, збереження й власні елементи керування. Це відправна точка для вивчення коду, а не довідник API. Використання: [посібник користувача](user-guide.md).

<a id="start-here"></a>

## Почніть тут

1. [Зберіть програму](build.md) через MSVC/NMAKE.
2. [Запустіть відповідні регресійні тести](../tests/regression/README.md) локально, у [виділеному клієнті Hyper-V](../tests/client/README.md) або через [робочий процес GitHub Actions](../tests/regression/README.md#run-on-github).
3. Прочитайте [архітектуру оболонки](native-shell-view.md) перед зміною життєвого циклу, відновлення чи ідентичності елементів.

<a id="code-map"></a>

## Карта коду

Увесь вихідний код програми міститься в `src/`.

| Ділянка | Відправні точки |
| --- | --- |
| Запуск, життєвий цикл і відновлення | `main.cpp`, `ProcessLifetime`, `CrashRecovery` |
| Вікна папок і просторова навігація | `ItemWindow`, `FolderWindow`, `CreateItemWindow` |
| Нативне подання файлів | `ShellViewHost`, `ShellViewSettings`, `ShellViewSelection`, `ShellViewIcons`, `ShellViewFilter` |
| Ідентичність і збережений стан | `FolderIdentity`, `FolderStateStore`, `ClosedWindows` |
| Розміщення й жести | `WindowPlacement`, `WindowResizeGesture`, `WindowShortcuts.h` |
| Настройки й переклади | `Settings`, `SettingsDialog`, `ShortcutSettingsPage`, `dialog.*.rc`, `resource.*.rc` |
| Пошук і перегляд | `SearchBox`, `Everything`, `Peek` |
| Меню заголовка й групи | `TitleMenu.h`, `TitleMenuDialog`, `TitleMenuRenderer`, `FolderGroups.cpp` |
| Змішане сортування | `MixedFolder`, `MixedFolderProvider` |
| Оновлення | `Update*` |

Збирання, інсталятор, тести й сайт мають окремі входи: `Makefile` / `build.cmd`, `installer/`, `tests/` і `website/`. Нові одиниці C++ додавайте до відповідного списку об’єктів Makefile. Текст інтерфейсу зберігайте в мовних ресурсах зі збереженням кодування.

<a id="boundaries-to-preserve"></a>

## Межі, які слід зберігати

- Папка має одне вікно, також між процесами FileSpacer. Ідентичність отримується до завантаження подання оболонки. `FolderIdentity` використовує нативну ідентичність локального NTFS, нормалізовані UNC-шляхи віддалених папок, шляхи інших локальних файлових систем і імена розбору оболонки для віртуальних папок.
- Загальні настройки належать реєстру, стан папок — SQLite. Геометрія, подання й положення піктограм є незалежно наявними частинами знімка. Відсутні дані не стирають відомої частини. Головне з’єднання бази належить потоку інтерфейсу; фонові читачі мають власні. Транзакції запису короткі й поза викликами оболонки/мережі.
- Відфільтроване або неготове подання не є повним розташуванням піктограм. Не зберігайте його як повне. Блокування захищає геометрію й подання; положення піктограм і далі зберігаються.
- Помилка доступу не доводить видалення. Зберігайте стан, доки видалення не підтверджено або не діють правила зберігання/квот.
- Виклики оболонки й модальні меню можуть обробляти повідомлення та закривати власника до повернення. Посилання COM зберігає об’єкт C++, а не вікно чи подання. Повторно перевіряйте життєвий цикл і покоління спостереження.
