Public partial-selection reader — adopted in codex/reactivity-hybrid
2026-11-08 — host Windows x64 — baseline commit 38fb0a07

Scope
-----
Extend the existing public complete-selection reader to partial selections of
at least 1024 items in ungrouped free Icon/SmallIcon views (all four icon sizes).
The complete-selection threshold remains 128. Smaller partial selections,
grouping, automatic layout, duplicate selected coordinates and invalid captures
retain native GetSelection. Cancellation returns E_ABORT without stale fallback.

The reader enumerates selected view indices with IFolderView2::GetSelectedItem,
using Item(0)/GetSelectionState for index zero. It accepts either inclusive or
exclusive forward iteration, without undocumented negative starting indices.
It captures only selected PIDLs/positions, uses the existing native spatial
ordering (column order, rotated only when the focused item is selected), and
constructs an owning IShellItemArray with SHCreateShellItemArray. A second index
pass detects same-count subset replacement. Final counts and focus are checked
AFTER that pass, so a late focus change cannot publish an obsolete ordering.
No private discovery, method, function pointer, offset or startup state is added.
The existing private capability is used only to prepare/clear test selections;
all calls measured in the new capture implementation use public APIs.

Investigation and decisions
---------------------------
Pilot 27 rows: correct identity sets for all rotations, native order only when
rotating to a selected focus; an unselected focus leaves column order unchanged.
Dense partial capture initially fell from about 245–261 ms to 31–33 ms before
the second consistency pass. Final numbers above include that pass.
Small 128- and 512-item subsets showed no useful gain (a few milliseconds in
both implementations), so the adopted partial path begins at 1024 items.
