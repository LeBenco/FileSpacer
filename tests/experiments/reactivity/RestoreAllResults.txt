Complete-selection restoration investigation, 2026-11-07

Qualification update (same day)
-------------------------------
The historical Content row below requested FVM_CONTENT with custom layout flags.
The classic host displays tiles for that request; FS has no Content menu command.
It is not a measurement of real modern Content. Also, the old host omitted FS's
FWF_NOWEBVIEW and FWF_NOHEADERINALLVIEWS. Its timings remain raw observations of
that fixture, not an exact reproduction of the FS presentation. LayoutPathResults.txt
records the corrected host, real modern Content and the remaining phase analysis.

Scope
-----
Production restoreReopenSelection, real Shell views, 5000 files, Windows x64
Debug with CFG. The reference is the exact ShellViewSelection.cpp from 9042bea,
not the original FileSpacer release. Both executables use the same driver and
other production units. List and Details use FVO_DEFAULT; the other FS views
use FVO_CUSTOMPOSITION | FVO_CUSTOMORDERING. All view rectangles are 800x400.
Readiness requires the real completed-enumeration event.

FS restores an actual captureReopenSelection snapshot, including selection,
focus and scrolling. Explorer performs its native Select All command through
the same documented interface when available. These are related operations,
not identical application workflows or opening-time measurements.

Cause and change
----------------
The existing qualified Select All adapter was bypassed when reopening a saved
complete selection: restoration selected each child separately. The candidate
proves the exact complete identity set, invokes the documented bulk operation,
and proves the resulting selection again. It adds no private method, offset,
executable patch or unqualified indirect call. It reuses the existing qualified
binding; its absence still permits public bulk selection in arranged views.
The public free-placement path remains unchanged to avoid a measured slowdown
of the unqualified bulk path. Small and partial selections retain per-item
restoration. Differently encoded opaque IDs conservatively take that path.

Safety and regression coverage
------------------------------
Cancellation during identity proof returns E_ABORT, consumes the pending state
once and leaves the exact empty selection unchanged. Duplicate saved identities
restore the expected 4999 unique children without a global operation. Replacing
one file with a different identity while retaining a 5000-item count restores
only the 4999 surviving saved identities, excluding the new file.

Real-Shell regression cases 18/02-Persistance and 18/03-RedessinGrandDossier
passed in AgentWin10. This does not constitute a complete regression-suite run.

Reproduction
------------
Run-Experiment.ps1 -Case RestoreAll -TimeoutSeconds 900
Run-Experiment.ps1 -Case RestoreFreeBalance -TimeoutSeconds 900
Run-Experiment.ps1 -Case RestoreVisual -TimeoutSeconds 900

The wrapper compiles through the existing tests.cmd/NMAKE/MSVC path and runs
only in AgentWin10. The driver rejects execution outside that dedicated VM.
ReferenceRevision defaults to 9042bea. Optional CacheRecord accepts a 160-byte
runtime-generated descriptor from this VM; the native loader still validates
the exact loaded DLL, operands and CFG. No prepared Windows profile is shipped.
Fresh symbol preparation hit a download limit on this VM; successful comparisons
reuse a previously qualified descriptor for that same VM image. This work does
not establish compatibility with other Windows images.

The viewport dimensions match, but the classic FS layouts are not visually
identical to modern Explorer. In particular the Content screenshots show FS
displaying a denser, multi-column arrangement with its column header, while
Explorer shows full-width content rows. Thus this is a comparison of each
product's requested mode, not an equal-visible-item-count renderer benchmark.
Tiles/Content retain about 200 ms of observed extra presentation latency on
this pass, while remaining below 500 ms. No causal attribution of that residual
gap to layout density alone has been established.

The guest case and cleanup returned PASS/0. After collection, the host launcher's
poll of protected last-run.json failed with Access denied, so its command exit
was nonzero. This transport failure is retained, not relabelled PASS. A separate
authorized read verified the matching controller record Complete with no error,
TaskExitCode/LastTaskResult 0, the matching guest run ID, RunnerExitCode 0 and no
cleanup errors. The native visual-test result is valid; the launch command's
permission failure is a separate limitation. No VM infrastructure was changed.

The remaining per-item path for arbitrary subsets and the cost of checking an
already identical large selection remain investigation candidates. The complete
set shortcut is not evidence that either case has been accelerated.
