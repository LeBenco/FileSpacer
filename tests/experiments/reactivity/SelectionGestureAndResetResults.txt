Selection gestures and public view recreation -- 8 November 2026
===============================================================

Decision
--------
No additional product acceleration is adopted by this investigation. The
attempted early-Escape change was reverted. FolderWindow.cpp and
ShellViewSelection.cpp retain their previously adopted behavior.

Stop pursuing the modest public recreation gain. Prioritize operations taking
seconds, especially deselection by an ordinary blank click in free Tiles with
5,000 files. Do not infer user-visible latency from the private API's duration.

Actual FileSpacer gesture coverage
--------------------------------
55-SelectionGestures.ps1 runs the Debug application in the runner's isolated
/test registry/database namespace. main.cpp accepts FS_SELECTION_PRODUCT_CACHE
only in that Debug test mode, with discovery disabled. Ordinary test runs keep
the public path; normal application startup is unchanged.

The fixture uses the real FS display menu to choose the classic profile before
changing arrangement. Directly changing IFolderView's mode from modern Details
does not establish that renderer transition and is not sufficient evidence.

One completed host run checked 24 gestures with 256 files:
 build/regression/20261108-110320-2ba522283b8c46b2b5857ba1c54b175b

For medium Icons, Tiles, free Icons and free Tiles:
 - Escape: exactly one qualified native-range clear in every private arm.
 - Blank click and click on an already selected item: zero adapter range calls.
 - Public arms: zero private range calls for all gestures.
 - All selected identities and the fixture item count were correct.

Thus Escape already reaches the adopted private implementation. Ordinary mouse
deselection still belongs to the Shell. This result proves routing, not that
the entire mouse procedure is slow in every representation.

Counter integrity
-----------------
The observer reads only its expected Debug executable's own counter, using its
matching local PDB. Module lookup uses the image path, not module-list order.
The selected address must be writable, committed image data belonging to that
executable; code and heap addresses are rejected. No injected code, patched
instructions or modified vtables are used.

An initial observer incorrectly accepted the eight-byte rangeCalls procedure
instead of its untyped public data symbol. Those zero deltas are invalid.
Filtering CodeView symbol tags, recognizing the static data name and checking
the memory region fixed this. Two small public/private contracts passed after
the module lookup correction:
 build/regression/20261108-110938-7312bfc0a14a40df9ad1b353513391c1

The counter subprocess now uses the existing CreateNoWindow process recorder.
It must not allocate a console and disturb focus or accessibility observation.

---------------------
A separate MSVC/NMAKE executable used HEAD's FolderWindow.cpp with the same
test-cache support and other objects. Three host Escape measurements at 5,000
medium Icons were compared with the attempted pretranslation change:

                       reference              early Escape

The variation and UIA traffic make these unsuitable as native performance
figures. They do not demonstrate a gain. The candidate was removed rather than
adding a keyboard path without a demonstrated benefit. A later ancillary rename
fixture timed out setting edit text; no rename change is delivered.

Rejected public recreation
--------------------------
PublicViewResetTests.cpp is an independent real-Shell experiment. It uses only
public calls in its clear/recreate workflow; no private adapter is initialized.
Scope: 5,000 files, classic arranged Icons/Tiles, explicit ascending or descending
name sort, no grouping, and an 800 x 400 Shell viewport. It does not cover free
positions, manual ordering, virtual folders or the modern Content view.

The timed workflow includes snapshot capture, destruction and release of the
old browser, creation/navigation, actual EnumDone, restoration, synchronous
RedrawWindow and DwmFlush. Full FS application callbacks/database work are not
included. This is forced composition, not a desktop-duplication settling test.

                             public clear    recreate       validation
 medium, one passing pair    720.714 ms      623.979 ms      initially correct
 medium, separate trial      818.142 ms      667.052 ms      later focus failure
 Tiles                       773.512 ms      589.408 ms      later focus failure

Order, settings, logical focus, selection anchor, viewport, retained arrays and
empty selection were checked. Rechecking after message dispatch exposed loss
of keyboard focus in recreated views. Those rows are failures, not accepted
performance gains. The cause of the focus loss is not established. Even the
optimistic times remain hundreds of milliseconds and do not approach the
already adopted private clear. No integration is justified here.

Large mouse case: still unvalidated
----------------------------------
The opt-in escape-background gesture tests an upper bound for clearing before
the ordinary click. It includes another native hit test, Escape, observation of
empty selection, the click and composition. It does not implement a production
mouse hook and does not prove drag, cut or reentrant input behavior safe.

The 5,000-file host attempts did not complete their comparison: UIA traffic
occupied the GUI thread and the foreground guard later rejected input. One
run spent tens of seconds locating a blank point as well. These observations
are not validated FS clear times and must not be mixed with the API results in
RemainingSelectionResults.txt.

Noninvasive stacks repeatedly showed:
 getProcessMessage -> PeekMessage -> UIAutomationCore provider/event handling
 -> SendMessage(LVM_GETITEMW).

The sender was not identified. A bounded handles-only diagnostic was
inconclusive; no accessibility service or user application was disabled.

Reproduce the actual-app checks
------------------------------
From CMD in the worktree, with FileSpacer closed and the test desktop available:

 powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\experiments\reactivity\Run-SelectionGestures.ps1

Supply a current runtime-qualified descriptor directory with FS_GESTURE_CACHE
when it is not in build\remaining-selection\cache. The launcher builds its own
counter helper and uses tests.cmd for state backup/restore and scoped cleanup.

Optional environment controls:
 FS_GESTURE_PUBLIC=1              also test the public arm
 FS_GESTURE_COUNT=5000            default 256; minimum 128
 FS_GESTURE_VIEWS=free-tiles       comma-separated view names listed above
 FS_GESTURE_ACTIONS=background,escape-background
 FS_GESTURE_REPETITIONS=3         default 1; maximum 3

CSV columns distinguish selected-state observation, DwmFlush completion,
private call counts, target-location setup and the candidate's extra hit test.
Current CSV numbers use invariant decimal formatting. Earlier quoted French
decimal values require fr-FR parsing. A DwmFlush timestamp is not proof that a
screen region has settled. Use the existing visual observer for that question.

The public-only experiment can be run from an x64 MSVC CMD prompt with:
 powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\experiments\reactivity\56-PublicViewReset.ps1 -View tiles -Repetitions 1

Validation of retained changes
------------------------------
Debug application and native helpers built with MSVC /W4 and CFG; the new
shadowing warning in the initial cache-path edit was corrected. Both
clang-tidy and Cppcheck completed on main.cpp, RemainingSelectionTests.cpp and
PublicViewResetTests.cpp, including their real/local headers as appropriate.
Baseline comparisons found no new diagnostic in main.cpp. Test-only diagnostics
concern the SDK's reserved compatibility macro, adjacent string parameters,
fixture .cpp inclusion and Win32 enum flag expressions. Static verdict: REVIEW;
no confirmed new correctness defect. Experimental functional failures above
remain failures and are not converted into static-analysis success.

The temporary screen-saver state whose restoration failed during one host run
was restored to its recorded original value. No manual FileSpacer kill was
issued. Subsequent inspection found forced termination in the legacy controller;
see HostClickPresentationResults.txt for the correction and the watchdog fix.
No release build, main-worktree merge or push.
