Watchdog defect discovered and corrected
----------------------------------------
The legacy controller forcibly killed an entire scenario tree on timeout and
also killed leftover FileSpacer processes after a normal-close grace period.
The 900-second attempt explicitly stopped FileSpacer PID 40844. Earlier notes
claiming no FileSpacer termination were therefore too strong: no manual kill
was issued, but controller-enforced termination was possible and occurred.

The controller now stops only its owned scenario process, never its tree.
The shared stop helper explicitly refuses FileSpacer. Application cleanup
requests normal closure and records leftovers without killing them. If the
tested application remains alive, test-registry/database backups are retained
and restoration is deferred, avoiding writes against its active test state.
Desktop-activity settings are still restored. A timed-out case stops the suite
because preserved descendants could prevent isolation. Subsequent tests also
cannot proceed while the application remains open.

The process contract uses a real harmless parent/child pair: stop the parent,
verify the child is still alive, then signal it to exit normally. It does not
terminate a real FileSpacer instance to test this rule. The contract and the
prepared-runner contract both passed in:
 build/regression/20261108-141120-02a8bf61ff97440892af0a03626ccd8d

Precise stationary-button protocol
----------------------------------
FS_GESTURE_PRESENTATION=1 builds GesturePresentationTests.cpp. The observer
checks the fixture PID, executable, root class, foreground and coverage; it
captures only the real Shell rectangle and requires a lasting visible change,
stable final image, unchanged geometry and foreground. Named events coordinate
readiness and the start marker. Frame hashes, before/first/final bitmaps and
presentation timestamps are retained, including coalescing quality.

The pointer is positioned on a previously verified target before observation.
ClickControlAtPointer checks exact pointer coordinates, foreground and native
target, then timestamps immediately before SendInput without moving the pointer.
The CSV subtracts the observer-to-input marker interval from visible timings.
The pointer is parked outside the Shell after the action to exclude tooltips.

escape-background retains its extra remote hit test in the measured sequence.
escape-background-once is a distinct experiment: it verifies the blank point
in preparation, then measures Escape plus a guarded click, without repeating
that remote hit test. It does not implement or validate a production mouse hook,
drag/cut semantics or an internal in-message hit-test optimization.

FS_GESTURE_PRESEED=1 optionally prepares one persisted view on 128 files,
closes it, creates the remaining files, and reopens the actual saved view.
It is a different preparation scenario; its timeout above remains a failure.

The launcher accepts -TimeoutSeconds (30..900, default 300). Use a larger limit
explicitly for large fixtures; the application itself is no longer force-killed
by the controller. All fixtures and native artifacts stay under the project.

Conclusion: both 5,000-file interactive cases are now measured successfully,
but the private call's millisecond API result does not translate to a massive
gain in the measured GUI sequence: 54.09 seconds versus 50.86 seconds here.
One sample of two different gestures cannot establish a percentage gain.
No automatic preclear mouse hook is adopted on this evidence. The unresolved
latency is around the complete input/message/presentation procedure, and
further investigation must identify it rather than extrapolate API timing.
