# Архітектура нативного подання оболонки

Прочитайте перед зміною розміщення подання, відновлення стану чи межі між елементами оболонки та просторовими вікнами. Загальна карта: [Робота над FileSpacer](technical/README.md).

<a id="responsibilities"></a>

## Відповідальність компонентів

`ShellViewHost` вбудовує `CLSID_ExplorerBrowser`. Windows керує переліком, відображенням, піктограмами, режимами й файловими операціями. `FolderWindow` керує просторовою навігацією та координує збереження. Робочі параметри — `FVO_CUSTOMPOSITION | FVO_CUSTOMORDERING` без примусового `FVO_VISTALAYOUT`; віртуальні папки можуть вибирати початковий вигляд. `EBO_NOPERSISTVIEWSTATE` залишає збереження папок під контролем FileSpacer.

| Компонент | Відповідальність |
| --- | --- |
| `ShellViewHost` | Життєвий цикл браузера, навігація, доступ і публічні події. |
| `ShellViewSettings` | Захоплення/застосування режиму, розміру, прапорців, стовпців, сортування й групування. |
| `ShellViewSelection` | Вибір, фокус і одноразовий знімок відкриття/прокручування. |
| `ShellViewIcons` | Нативні ідентичності й вільні положення піктограм. |
| `ShellViewFilter` | Фільтр імен через `IFolderFilter`. |
| `FolderStateStore` | Незалежні частини стану, транзакції, блокування й зберігання. |

Операції подання використовують публічні COM-інтерфейси замість пошуку чи підкласування дочірніх елементів оболонки. Вузький виняток — тло вибраного напису нижче. Тести можуть досліджувати елементи для спостереження жестів; ця інструментація не є залежністю програми.

<a id="readiness-restoration-and-lifetime"></a>

## Готовність, відновлення й життєвий цикл

Завершення навігації, створення подання й завершення переліку — різні події. `OnViewCreated` не означає готовності вмісту. Спостерігайте публічні сигнали; час або кількість елементів не доводять готовності.

Сповіщення містять покоління спостереження подання. Скасуйте його до відписки або знищення й ігноруйте старі повідомлення. Одноразове відновлення позначайте використаним до повторно вхідних COM-викликів. Якщо настройки спричиняють новий перелік, дочекайтеся його завершення перед відновленням положень/вибору чи збереженням.

Виклики оболонки, меню й оновлення можуть обробляти повідомлення. Утримуйте COM-посилання й перевіряйте, чи існують власник і подання. Посилання захищає C++-об’єкт, а не `HWND` чи ресурси браузера. Спрямовуйте оновлення й команди через `FolderWindow::refreshView()` та `invokeViewCommand()`, щоб захист глибини навігації безпечно відкладав знищення. Застаріле продовження не відновлює подання й не планує запис.

Геометрія, подання й піктограми — окремі частини знімка. Помилка захоплення залишає відому частину. Захоплення відфільтрованих положень повертає `S_FALSE`; зберігайте лише за `S_OK`. Порожній, відфільтрований чи неповністю перелічений вміст не є повним розташуванням. Тимчасовий перегляд меню Подання також не потрапляє до постійного стану.

Вибір і фокус елемента відновлюються незалежно, один раз, без перехоплення фокуса клавіатури. Очищення через `SelectItem(nullptr, SVSI_DESELECTOTHERS)` не має містити `SVSI_NOTAKEFOCUS`; цей прапорець належить цільовому елементу. Перехід угору не вибирає джерело автоматично й не замінює вибір відкритого предка.

<a id="mixed-filefolder-sorting"></a>

## Спільне сортування файлів і папок

За змішаного сортування `MixedFolder` надає вузол оболонки в локальних даних FileSpacer із користувацькою COM-реєстрацією. `FileSpacerFolder.dll` реалізує `IShellFolder2` та `IPersistFolder2` і створює нативне подання через `SHCreateShellFolderView`. Хостом лишається `IExplorerBrowser`. Віртуальні папки й архіви зберігають постачальника Windows. Програма й DLL розгортаються разом.

Лише корінь постачальника має власну ідентичність вузла. Дочірні елементи зберігають незмінені відносні PIDL нативної папки. Перелік, метадані, піктограми, меню, об’єкти передавання й дії делегуються базовій папці. Стовпці порівнюються без пріоритету папок; ідентичність — нативно. Вільний режим зберігає постачальника й положення без примусового автоупорядкування.

Приватний контракт `IMixedFolder::NativeItem` перетинає межу DLL FileSpacer. Для справжнього елемента файлової системи поза постачальником використовуйте `nativeShellItem()` / `nativeViewSelection()`. SQLite зберігає нативні дочірні ID для однакового вибору й положень після зміни настройок. Не обгортайте й не переінтерпретовуйте дочірні PIDL. Подання підписується на зміни справжнього кореня через `SFVM_GETNOTIFY` без дублювання сповіщень вузла.

Реєстрацію й вузол ізольовано в `/test`. Тести видаляють лише власну реєстрацію й каталог. Звичайне видалення прибирає реєстрацію FileSpacer.

<a id="selected-name-background-and-scrolling"></a>

## Тло вибраного імені й прокручування

`ShellViewLabels.h` необов’язково заповнює непрозоре тло напису одного вибраного елемента в режимі піктограм. Windows і далі малює й розгортає текст. Множинний вибір, лише фокус та інші режими лишаються нативними.

Адаптація підкласовує лише публічне вікно `IShellView::GetWindow` у його потоці. Читає `NM_CUSTOMDRAW` із перевіреної ListView цього подання й використовує документовані операції читання. Перевіряйте фактичний вибір, а не лише `CDIS_SELECTED`. Зберігайте `DefSubclassProc` та результат; не додавайте `CDRF_SKIPDEFAULT`. Обробник не має вказівника FileSpacer і прибирає себе за `WM_NCDESTROY`.

Цей шлях сповіщень — залежна від реалізації адаптація відображення, а не загальний контракт оболонки для розгортання написів. Якщо передумови чи сповіщення зникають, залишайте стандартне малювання. Не узагальнюйте на власне малювання кількох написів або операції подання.

Повторне відкриття Таблиці/Списку відновлює якір першого видимого рядка, а не точні пікселі. `ShellViewSelection` знаходить його через `IFolderView::Items` і положення в клієнтській області під доступним заголовком стовпців. Відновлення показує останній елемент, потім якір із вимкненим перемальовуванням без захоплення фокуса. Піктограми використовують непрокручені положення й відкриваються вгорі. `IFolderView2::GetVisibleItem` не є запитом видимої області; не припускайте прокручування в `GetViewStateStream`.

<a id="activation-and-external-folders"></a>

## Активація й зовнішні папки

За збереження вибору звичайне ліве клацання тла активує неактивне подання без очищення. Цикл використовує `WM_ACTIVATE` / `WA_CLICKACTIVE` і справжню ціль подання перед відкиданням першого натискання тла. Клацання заголовка не має пригнічувати пізніше клієнтське клацання. Елементи, праві клацання, заголовки, прокручування й активні вікна лишаються звичайними. `WM_MOUSEACTIVATE` зовнішньої рамки ненадійний через вікна оболонки.

Панель керування відкривається зовні через `IOpenControlPanel::Open`. Порівнюйте ідентичності оболонки, а не перекладені імена чи декодовані PIDL. Зберігайте вихідну папку й вибір.
